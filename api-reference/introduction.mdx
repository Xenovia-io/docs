Xenovia exposes two HTTP surfaces. This reference covers the **management API** served by the control plane. Inference and SDK traffic goes to the **runtime** instead, at your agent's endpoint, and is documented under [Integrations](/integrations/overview).

| Surface | Base URL | Credential | Used for |
|---------|----------|------------|----------|
| Management API (this reference) | `https://cp.xenovia.io/api/v1` | Organization API key `ak_…` or a dashboard session | Creating and configuring agents, providers, policies and alerts; reading sessions, traces and audit logs |
| Runtime | `https://runtime.xenovia.io/{agent_id}/v1` and `https://runtime.xenovia.io/v1/execute` | Agent API key `xe_…` | `POST /chat/completions` and `POST /responses` from your application; `POST /v1/execute` from the Python SDK |

The two credentials are not interchangeable: the management API rejects `xe_…` keys and the runtime rejects `ak_…` keys. See [Authentication](/api-reference/authentication).

## Base URL

```
https://cp.xenovia.io/api/v1
```

The OpenAPI document is published at `https://cp.xenovia.io/openapi.json`; the endpoint pages in this reference are generated from it.

## Conventions

- **JSON everywhere.** Request and response bodies are `application/json`.
- **Identifiers.** Agents, providers, policies, sessions and traces use UUIDs. The `org_id` path parameter is the Clerk organization id (`org_…`), visible under Settings in the dashboard.
- **Status codes.** `201` on create and attach, `204` on delete and other empty responses, `200` otherwise. See [Errors and Limits](/api-reference/errors-and-limits).
- **Pagination.** List endpoints take `limit` (default `20`, maximum `100`) and `offset` (default `0`) and return `{ "items": [...], "total": n, "limit": n, "offset": n }`. Alert events and notifications default to `50`, alert rules to `100`. Guardrails, deployments and policy templates return a bare array instead.
- **Request ids.** Every response carries an `X-Request-ID` header. Send your own value to have it echoed and recorded in the audit log; otherwise one is generated.
- **No idempotency keys.** Retrying a `POST` creates a second resource, or returns `409` where names are unique (agents, providers, policies, guardrails).
- **Propagation.** Configuration changes are written through to the runtime immediately and revalidated by each runtime instance about every five minutes. A change to an agent, provider, policy or guardrail is live within that window.

## Tenancy

Every request is scoped to one organization: the organization that owns the API key, or the organization selected in the dashboard session. Resources that belong to another organization return `404`, not `403`.

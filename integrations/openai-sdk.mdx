## Setup

```bash
export XENOVIA_API_KEY=xe_...
export XENOVIA_AGENT_ID=your-agent-id
```

<Tabs>
  <Tab title="Python">
    ```bash
    pip install openai
    ```

    ```python
    import os
    from openai import OpenAI

    client = OpenAI(
        api_key=os.environ["XENOVIA_API_KEY"],
        base_url=f"https://runtime.xenovia.io/{os.environ['XENOVIA_AGENT_ID']}/v1"
    )

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Hello"}]
    )
    print(response.choices[0].message.content)
    ```
  </Tab>
  <Tab title="Node.js">
    ```bash
    npm install openai
    ```

## Streaming

Streaming works without any additional configuration. The runtime stamps `X-Xenovia-Session-Id` and `X-Xenovia-Trace-Id` into the response headers before the first byte.

<Tabs>
  <Tab title="Python">
    ```python
    stream = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Count to 5"}],
        stream=True
    )
    for chunk in stream:
        print(chunk.choices[0].delta.content or "", end="")
    ```
  </Tab>
  <Tab title="Node.js">
    ```typescript
    const stream = await client.chat.completions.create({
      model: "gpt-4o-mini",
      messages: [{ role: "user", content: "Count to 5" }],
      stream: true
    })
    for await (const chunk of stream) {
      process.stdout.write(chunk.choices[0]?.delta?.content ?? "")
    }
    ```
  </Tab>
</Tabs>

## Tool calling

Tool definitions pass through unchanged. Xenovia records tool call names and arguments in the trace and evaluates them against your request-stage Rego policy before forwarding.

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {"type": "string"}
                },
                "required": ["location"]
            }
        }
    }
]

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What's the weather in London?"}],
    tools=tools
)
```

If a tool name matches a block rule in your Rego policy, the request returns `403` before reaching the upstream LLM.

## Sessions

Pass `X-Xenovia-Session-Id` (a valid UUID) to group related calls into a session. During a simulation, forward the value Xenovia sent instead (see [Forwarding the simulation session](#forwarding-the-simulation-session)). All turns under that session ID appear together in **Sessions** with a per-session turn counter.

<Tabs>
  <Tab title="Python">
    ```python
    import uuid

    client = OpenAI(
        api_key=os.environ["XENOVIA_API_KEY"],
        base_url=f"https://runtime.xenovia.io/{os.environ['XENOVIA_AGENT_ID']}/v1",
        default_headers={"X-Xenovia-Session-Id": str(uuid.uuid4())}
    )
    ```
  </Tab>
  <Tab title="Node.js">
    ```typescript
    import { randomUUID } from "crypto"

    const client = new OpenAI({
      apiKey: process.env.XENOVIA_API_KEY,
      baseURL: `https://runtime.xenovia.io/${process.env.XENOVIA_AGENT_ID}/v1`,
      defaultHeaders: { "X-Xenovia-Session-Id": randomUUID() }
    })
    ```
  </Tab>
</Tabs>

If you omit the header, Xenovia resolves a session automatically using message fingerprinting or the `user` field. See [Runtime Architecture](/platform/runtime-architecture) for the full five-strategy chain.

## Forwarding the simulation session

[Simulation](/platform/simulation) sends your agent an `X-Xenovia-Session-Id` header with every turn. Forward that value, exactly as received, on every model call the turn makes, so Xenovia can see the calls, grade policy and tool checks, and apply the run's [mode and model](/platform/simulation#enforce-and-observe-only). On the Xenovia cloud runtime it is a signed value (`xsim1.…`), not a UUID, and on a customer-hosted runtime a plain UUID. Either way, don't parse, trim or replace it: a changed signed value is rejected with `400`.

<Tabs>
  <Tab title="Python">
    The [Xenovia Python SDK](/integrations/xenovia-sdk#simulation-session-forwarding) reads the header in a middleware and adds it to each model call made while handling that request:

    ```bash
    pip install "xenovia-sdk>=0.3.0" openai fastapi
    ```

    ```python
    from fastapi import FastAPI
    from openai import OpenAI
    from xenovia_sdk import XenoviaASGIMiddleware, openai_client_kwargs

    app = FastAPI()
    app.add_middleware(XenoviaASGIMiddleware)
    client = OpenAI(**openai_client_kwargs())  # base_url, api_key and a session-forwarding http_client

    @app.post("/chat")
    def chat(body: dict):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": body["message"]}]
        )
        return {"reply": response.choices[0].message.content}
    ```

    `openai_client_kwargs()` reads `XENOVIA_API_KEY` and `XENOVIA_AGENT_ID` (and `XENOVIA_RUNTIME_URL`, default `https://runtime.xenovia.io`). Use `AsyncOpenAI(**openai_client_kwargs(async_=True))` for async code, and `app.wsgi_app = XenoviaWSGIMiddleware(app.wsgi_app)` for Flask. Requests without the header are sent without it, as before.
  </Tab>
  <Tab title="Node.js">
    Read the header from the incoming request and pass it on each call. This example uses Express:

    ```bash
    npm install openai express
    ```

    ```typescript
    import express from "express"
    import OpenAI from "openai"

    const app = express()
    app.use(express.json())

    const client = new OpenAI({
      apiKey: process.env.XENOVIA_API_KEY,
      baseURL: `https://runtime.xenovia.io/${process.env.XENOVIA_AGENT_ID}/v1`
    })

    app.post("/chat", async (req, res) => {
      const session = req.get("X-Xenovia-Session-Id") // forward verbatim
      const response = await client.chat.completions.create(
        {
          model: "gpt-4o-mini",
          messages: [{ role: "user", content: req.body.message }]
        },
        { headers: session ? { "X-Xenovia-Session-Id": session } : {} }
      )
      res.json({ reply: response.choices[0].message.content })
    })

    app.listen(8000)
    ```

    Don't set the session in `defaultHeaders` on a shared client: concurrent requests would overwrite each other's session.
  </Tab>
</Tabs>

## Custom trace properties

Attach up to 20 `X-Xenovia-Property-*` headers to tag traces with application context. Keys must be ≤ 64 chars; values ≤ 512 chars; the `policy_` prefix is reserved.

```python
client = OpenAI(
    api_key=os.environ["XENOVIA_API_KEY"],
    base_url=f"https://runtime.xenovia.io/{os.environ['XENOVIA_AGENT_ID']}/v1",
    default_headers={
        "X-Xenovia-Session-Id": str(uuid.uuid4()),
        "X-Xenovia-Property-user-tier": "enterprise",
        "X-Xenovia-Property-feature": "document-summary"
    }
)
```

## Policy blocks

When a request is blocked by policy, the runtime returns `403 Forbidden`. The OpenAI SDK raises this as `PermissionDeniedError`. The `X-Xenovia-Trace-Id` response header identifies the blocking trace.

<Tabs>
  <Tab title="Python">
    ```python
    from openai import PermissionDeniedError

    try:
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": "Delete everything"}],
            tools=tools
        )
    except PermissionDeniedError as e:
        print(f"Blocked by policy: {e.message}")
    ```
  </Tab>
  <Tab title="Node.js">
    ```typescript
    import { PermissionDeniedError } from "openai"

    try {
      const response = await client.chat.completions.create({
        model: "gpt-4o-mini",
        messages: [{ role: "user", content: "Delete everything" }],
        tools
      })
    } catch (e) {
      if (e instanceof PermissionDeniedError) {
        console.log("Blocked by policy:", e.message)
      }
    }
    ```
  </Tab>
</Tabs>

## Reading trace headers

The response always includes trace headers you can log for correlation:

```python
import httpx
from openai import OpenAI

# Use httpx to access response headers
with httpx.Client() as http:
    resp = http.post(
        f"https://runtime.xenovia.io/{os.environ['XENOVIA_AGENT_ID']}/v1/chat/completions",
        headers={
            "Authorization": f"Bearer {os.environ['XENOVIA_API_KEY']}",
            "Content-Type": "application/json"
        },
        json={
            "model": "gpt-4o-mini",
            "messages": [{"role": "user", "content": "Hello"}]
        }
    )
    trace_id = resp.headers.get("X-Xenovia-Trace-Id")
    session_id = resp.headers.get("X-Xenovia-Session-Id")
    print(f"Trace: {trace_id}, Session: {session_id}")
```
